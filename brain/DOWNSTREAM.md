# DOWNSTREAM: the "run live or rerun" answer (G12.9g)

Operational sign-off for what happens to every downstream module once G12.9's
promotion (fold-count unification, Ellel uncapped, per-venue weather) changes
which rung is served at L1. Verified against the code (not assumed), see the
file:line references below.

## Rerun matrix

| Module | Reads served L1 forecast? | Action | Why |
|---|---|---|---|
| Deviation (`signals.deviation`) | No | Run live, no rerun needed | Reads `build_residual_stream` (`signals/residual.py:51-94`), whose expected value is the expanding DOW-median (Rung-1 baseline) and whose scale is the conformal quantile of DOW-median residuals. Architecturally decoupled from whichever rung is served at L1 (WP12 G12.7 verified 0/28 change) |
| Change-point (`signals.change_point`) | No | Run live, no rerun needed | Same residual stream (`signals/change_point.py:46,155`): DOW-median expected, DOW-median conformal scale. The served L1 model never enters it |
| Briefing (`signals.briefing`) | No, indirectly | Run live | Composes deviation + change-point + stock cover + checklist; inherits whatever those produce. Its own ranking/scoring maths is unchanged |
| Reasoning / attribution (`signals.residual.attribute`) | No | Run live | Enriches a flagged residual-stream null with exo/event candidates; reads the residual stream and exo/event tables, not the served forecast |
| Stock cover (`signals.stock_inventory`) | Yes, but a SEPARATE model | Rerun `reconcile` only if the reconcile base forecaster changes (it doesn't here); else no rerun | Cover reads `forecasts` where `model='mint_dowmedian'` (`signals/stock_inventory.py:40-49`, `A6_MODEL`), the MinT-reconciled DOW-median base (`hierarchy/reconcile.py:119`), NOT the L1 served Chronos/whatever-wins model. Also scoped to Beer Hall only (`VENUES_WITH_STOCK`), so Ellel's uncapping doesn't touch it at all |
| Served forecast / band (`/forecast`, `/stock/cover` band) | Yes, by definition | Already regenerated by promotion | This is the thing G12.9 changes; `ingest.refresh._promote_and_serve` re-persists it on every adoption |

**Headline:** the signal layer (deviation, change-point, briefing, reasoning)
is safe to run live with no rerun, because it is built on the DOW-median
residual stream, not the served forecast. G12.9's changes (n_folds=6 re-fit,
Ellel uncapped, per-venue weather) only affect the `/forecast` endpoint's L1
point forecast and conformal band for whichever venue re-fits and adopts a new
rung; promotion already regenerates that. Stock cover sits on a separate
MinT-DOW model and is unaffected by which L1 rung wins, and untouched for Ellel
specifically (out of `VENUES_WITH_STOCK` scope).

## Design note for the Discussion (not a code change)

The deviation layer deliberately uses the cheap DOW-median baseline rather than
the served forecaster (Chronos-2 or otherwise), so a better L1 forecaster does
not tighten deviation detection. This is a defensible separation (cheap,
stable, interpretable detection baseline), but it means forecast accuracy and
detection sensitivity are decoupled by choice, not oversight. Stated here so
it reads as a decision, not a gap.

## What G12.9 actually requires re-running, and why

- **Signal layer (deviation/change-point/briefing/reasoning), all venues:**
  smoke-checked once after G12.9c-e (Ellel uncapped, new weather basis) to
  confirm no crash on the newly-active Ellel rungs and the new coordinates.
  This is a smoke check, not a methodological rerun, per the table above.
- **`build_features` + ladder reports, Beer Hall / Ellel / Two River Taps:**
  re-run (G12.9e) because the weather coordinates changed for all three venues
  (each now has its own precise cell instead of the old shared `lancaster` /
  mis-located `trt_south`), so historical hindcast weather shifted slightly and
  the committed feature/report numbers need to match the new basis.
- **Ellel ladder (`python -m models.ladder --all-venues`):** re-run (G12.9c)
  because Ellel is now uncapped, so every rung competes, not just Rung 0/1.
- **T3 re-fit fold count (`ingest.refresh`):** no separate rerun needed beyond
  the ladder run above; the next live/forced re-fit naturally uses `n_folds=6`.
